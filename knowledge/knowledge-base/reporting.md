# Knowledge Base Reporting (KB 130)
**Source:** Product Foundation Courses → Knowledge Base - Knowledge Base Reporting → **"KB Microskills - Reporting" PDF** (slide deck; no course video) · **Help:** search `site:sprinklr.com/help knowledge base reporting dashboard import`

## What it is
Reporting/dashboards for Knowledge Base — monitoring how KB is used and the value it delivers, on both the **agent** and **customer-facing** sides.

## Why brands use it
1. Help managers understand the **value realisation** KB brings to customer-care operations.
2. Enable **knowledge resource management & tracking** by capturing **adoption, usage and satisfaction KPIs** — agent-facing and customer-facing.
3. Make analysis **easy, modular and simple** with a wide array of **visualisations** (pivot tables, stacked charts, counters, etc.).

Typical metrics seen on the sample dashboard (Knowledge Portal Website Analytics): **Top Referring Domains, Sessions Count, Bounce Rate, User Visits (last 24h), Page Views, Unique Visitors, Avg. Session Duration, Traffic from Google.**

## Configuration — prerequisites to set up KB reporting
The dashboard is created by **importing a template**. Two prerequisites:
1. **Workspace ID** — know which workspace the configuration must be **imported into** (specified in the import file).
2. **Dashboard import configuration file** — have the correct import config file (an Excel sheet of widget definitions: widget type, name, section, visualisation, size, position, filters, axis/series, etc.). Provided via the **"Import Template - Knowledge Base Reporting"** link in the deck.

Then run the **dashboard import** (the **Reporting Setup Demo** is shown in-platform) to plot the visualisations.
