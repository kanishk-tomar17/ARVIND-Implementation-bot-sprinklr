# Smart Routing / Smart Pairing (Unified Routing 028)
**Source:** Product Foundation Courses → Unified Routing / 028 Smart routing (video transcript) · **Help:** search `site:sprinklr.com/help smart pairing smart assignment AI routing agent score`

## What it is
**Smart routing (Smart Pairing)** is **AI-based assignment**. It learns from **past customer↔agent interactions** which agents resolve which issues best, then assigns incoming cases to the **best-suited agent** to maximise CSAT.

## Why it's different from skill/work-queue routing
- Normal routing needs **manual, periodic** proficiency updates by an admin; Smart Pairing has the **AI auto-calculate agent scores**, cyclically (each solved case feeds future assignments).
- Normal routing ignores **customer feedback** and **soft skills** (empathy, communication, patience). Smart Pairing relies on **customer feedback** + **perceived service-quality** scores.
- It can also use **demographic** (age, gender) and **behavioural/psychographic** customer data (fed to the model) to match the right agent.

## How it works (3 steps)
1. **Scoring** — per **intent**, each agent gets a score from the **review** after a case (e.g. CSAT 3/5 → 60% on intent X). Accumulates per intent per agent. Non-intent **service-quality** scores (courtesy, promptness, communication) come from reviews (e.g. *"friendly but slow"* → +courtesy, −promptness — and "slow" isn't universally bad; the AI reads it against customer data).
2. **Assignment** — with the agent scorecard, instead of FIFO/most-idle (or skill-match-then-FIFO), the **AI ranks agents** by customer data + intent and assigns to the **best** (even if not the most idle).
3. **Fine-tuning** — use reporting to review scores, tune the model, repeat.

## Enablement
1. **Raise a request to the product team.** They assess whether Smart Pairing helps, the available **intents**, and the **feedback data** (CSAT/NPS survey; else **predictive CSAT** auto-generated by AI; else text-based feedback).
2. Train the model on the feedback metric + customer data → generate agent scores → deploy.
3. Enable in **work queues** for a **% of cases** → measure → optimise → **scale**.

## In the platform
- Work queue → **Smart assignment** (DP-gated): tick to use it, then enter the **percentage of cases** routed via AI (e.g. 10% → the other 90% follow the queue's normal routing type; the 10% are assigned by AI scoring). Scale to **50%+** once optimised.

## Reporting
- Each case records whether it was **smart-assigned**. Compare metrics (**NPS, FCR, resolution rate**) **with vs without** smart assignment.
- Widget fields: case count, **smart assignment used**, work queues, NPS; plus **agent scores**, **predicted agents**, **predicted intents**.

## Notes / gaps
- Smart assignment **overrides** skill/idle logic from [[agent-skills]] for its share of traffic — roll out gradually (small % → measure → scale).
- Predictive CSAT means Smart Pairing works even without explicit surveys.
- Entirely **product-team-enabled** (DP + model training) — not self-serve config.
